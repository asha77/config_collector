# Использование YAUCC
## Установка и подготовка окружения
1. Установить git for windows. При установке выбрать редактор в качестве дефолтного для Git из установленных в системе (например, notepad). Остальные настройки по умолчанию.
2. Устанавливаем python. Текущая версия тестировалась с python-3.9. При установке поставить галку "Add python to path", остальные настройки "по умолчанию".
3. Создать папку, в которой будут запускаться скрипты, например, C:\scripts\.
4. В контекстном меню в папке (правая кнопка мыши в проводнике) выбрать "Git Bash Here". Запустится окно терминала git.
5. Наберите команду:
```
> git clone https://github.com/asha77/config_collector.git
```
Эта команда скачает код в папку config_collector.
Перейдите в папку:
```
> cd config_collector
```
Не закрывайте терминал.
6. Настроить окружение: в проводнике скопировать и переименовать файл ".env_init" в ".env". Файл ".env" будет использоваться только локально и не будет загружаться в репозиторий, т.к. не является его частью.
- открыть ".env" в notepad и изменить значения, чтобы файл выглядел так:
```
AUTH_USERNAME=<указать имя пользователя с которым можно авторизоваться на устройствах>
AUTH_PASSWORD=<указать пароль этого пользователя>
AUTH_SECONDARY=<пароль для enable, если у пользователя нет привилегий администратора для вывода show команд>
AUTH_STRICT_KEY=False
TRANSPORT=ssh2
TIMEOUT_SOCKET=20
TIMEOUT_TRANSPORT=20
TIMEOUT_OPS=360
WORKING_DIRECTORY=
MAX_WORKERS=10
SCRAPLI_DEBUG_LOG=False
BACKUP_CONFIG_FOLDER='путь куда сохранять копии конфигов edgecore'
OUTPUT_FOLDER='путь куда сохранять результаты выполнения команд'   # Если этот параметр отсутсвует или равен '', данные сохраняются в директории 'output' в рабочей директории скрипта (по умочанию)
```
Любые пробелы, табуляция после '=' или значений ключей должны отсутствовать.
7. Сформировать файл 'devices.txt' (см. пример файла 'devices_sample.txt' в репозитории и пояснения в README.md).
8. Файлы с исполняемыми командами ('xxx_commands.txt') для каждого вендора сформированы в дистрибутиве и могут модифицироваться пользователем под свои нужды.
Команды п.9-13 выполняются последовательно в терминале git.
9. В консоли git в папке config_collector запустить команду создания виртуального окружения python.
```
> python -m venv venv
```
10. Активировать виртуальное окружение python:
```
> source ./venv/scripts/activate
```
11. Обновить менеджер пакетов pip:
```> python.exe -m pip install --upgrade pip```

12. Установить необходимые библиотеки:
```> pip install -r requirements.txt```

13. Проверка версий установленного ПО:
```> python --version
> pip --version
> pip list
```

## Запуск скрипта
1. После успешного завершения процесса установки окружения, можно запустить YAUCC командой в терминале git:
```
>./start.sh
```
Скрипт сначала активирует venv, а затем запускает YAUCC c параметрами:
```
python -u -O main.py -d devices.txt
```

Опциональным параметром является ключ '-o'
```
python -u -O main.py -o -d devices.txt
```
Эта команда заставит скрипт сохранять результат каждый раз в одну и ту же папку 'output' и перезатирать предыдущие результаты.
Это удобно, если нужно организовать последовательную обработку собранных данных другим скриптом.

2. В ходе работы скрипт пытается подключиться к каждому устройству и получить результат команды 'show ver', чтобы определить доступность устройства и его тип.
Затем скрипт по очереди выполняет на каждом устройстве команды из файла "commands.txt", при этом он выводит в консоль и лог-файл информационные сообщения.
3. Результаты работы скрипта сохраняются в папки:
```
\config_collector\output\cnf_<data и время>\
```
При каждом запуске создается новая папка. После завершения работы скрипта папки можно архивировать или удалять.
4. После завершения работы скрипта он выдаст сообщение о завершении работы.
После этого можно забрать результат его работы в последней по времени папке с результатами:
```
\config_collector\output\cnf_<data и время>\
```
5. Если добавить опцию `-b` в строку запуска скрипта, после сбора требуемых данных скрипт также соберет резервные копии конфигураций известных ему устройств и сохранит их в папку BACKUP_CONFIG_FOLDER.
Если добавить опцию `-b N` в строку запуска скрипта, после сбора требуемых данных скрипт также соберет резервные копии конфигураций известных ему устройств, сохранит их в папку BACKUP_CONFIG_FOLDER и удалит резервные копии конфигураций, которые были собраны более чем N дней назад.

## Действия при возникновении ошибок
1. Если в процессе работы наблюдались ошибки и конфигурации не были собраны, следует создать git issue и приложить следующие данные:
   - файл 'logfile.txt' из последней по времени папки c результатами работы программы.
   - вывод или скрипшот команд проверки версий ПО из консоли git:
    ```
    > python --version
    > pip --version
    > pip list
    ```
   - файл scrapli.log из папки config_collector.
Либо все вышепереречисленное прислать разработчику (asha77@gmail.com).

## Обновление скрипта
Производится в консоли git командой:
```
> git pull
```

В результате git скачает изменения кода скрипта. Проверьте, не появились ли новые параметры в .env_init - и добавьте их в .env, задав соответствующие значения.
